# singaporebusinessbroker.com

Lead-generation website for **Singapore Business Broker**, the sell-side
brokerage practice of The Funding Assembly.

Static site: no framework, no build tooling, no runtime dependencies. Semantic
HTML generated by `build.py`, one stylesheet, one vanilla JS file (~6 KB) driving
the sticky header, scroll reveals, FAQ accordions and the sale-readiness
scorecard. Two self-hosted variable fonts (SIL OFL). Nothing is loaded from a
third-party origin, which is why the CSP in `vercel.json` can be as tight as it is.

### Relationship to businessbrokerinsingapore.com

The two sites are deliberately not duplicates — same firm, different angle,
different copy, different design system, no shared paragraphs. This one leads
with the named practice, published fees and the sale-readiness scorecard; the
other leads with the confidential-sale mechanism and a valuation estimator.
**When editing either site, do not copy prose between them** — duplicate content
across two domains owned by the same firm competes with itself in search.

## Editing

All HTML is generated. **Edit `build.py`, never the `index.html` files** — they
are overwritten on the next build, and CI fails the deploy if the committed HTML
does not match what `build.py` produces.

```bash
python3 build.py          # regenerate every page, the sitemap, robots.txt, favicon
python3 -m http.server 8000   # preview at http://localhost:8000
```

Things that live in more than one place and must be kept in sync:

- **WhatsApp number** `+65 8951 8821` — `WA_NUMBER` in `build.py` *and*
  `assets/js/main.js`.
- **Email** `eric.ong@thefundingassembly.com` — `EMAIL` in `build.py` *and* the
  `score-mail` handler in `assets/js/main.js`.
- **Fee tiers** — `FEE_TABLE` in `build.py`, quoted again in the homepage FAQ, the
  `/fees/` answer block and the hero "at a glance" card.
- **Scorecard weights and gap copy** — `QUESTIONS` in `assets/js/main.js`; the
  question wording and options live in `Q_OPTS` in `build.py`. The `name`
  attributes must match between the two.
- **`LASTMOD`** in `build.py` — the date stamped into `sitemap.xml`.

If you change the inline `js`-class bootstrap script in the shell, recompute its
SHA-256 and update the `script-src` hash in `vercel.json`, or every page will
break under CSP.

## Content rules

Copy follows The Funding Assembly's marketing standards, which are stricter than
typical broker marketing and are the reason the site reads the way it does:

- No fabricated numbers, testimonials, urgency or superiority claims.
- No guaranteed sale or price language — the firm sells a process, not an outcome.
- Client examples are disguised unless permission was given; the named references
  are the ones already published on thefundingassembly.com.
- The dual-agency position (sell-side mandate, separate 1% buy-side fee, both
  disclosed to both sides) is stated unprompted on the home, fees and buyer pages.
- The S$100,000 minimum and the "unsuitable below ~S$1.5M–S$2M" consequence are
  stated together, every time the minimum appears.
- No placeholder brackets may ever reach production.

### Facts worth adding when available

The About page is written to be true without them, but these would strengthen it
and are the first things a prospect checks:

- Year The Funding Assembly was founded, and its ACRA UEN.
- Number of completed transactions, and the year the strudel-manufacturer deal
  closed (currently described without a date so it cannot be mistaken for a live
  mandate).
- A founder photograph for the About page.

## Deployment

Pushes to `main` deploy to Vercel production via GitHub Actions
(`.github/workflows/deploy.yml`), which rebuilds, verifies the committed HTML is
current, then runs `deploy_vercel.py`. Requires the `VERCEL_TOKEN` repository
secret. The same script runs locally for an out-of-band deploy.

Vercel project: `singaporebusinessbroker`. DNS at the registrar:

| Type | Name | Value |
|---|---|---|
| A | @ | 76.76.21.21 |
| CNAME | www | cname.vercel-dns.com |

The apex redirects to `www` with a 308.

## Checks worth re-running after changes

Nothing is automated beyond the staleness check, but these caught real bugs
during the build and are quick:

- Structural: parse every page for unclosed tags and invalid JSON-LD.
- Contrast: compute the ratio for every text node against its painted
  background; the accent `--brass` was darkened to `#855E1E` to clear 4.5:1 on
  all three light surfaces.
- Heading order: one `<h1>` per page, no skipped levels.
- CSP: load the pages with the `vercel.json` headers applied and confirm the
  scorecard still computes.
